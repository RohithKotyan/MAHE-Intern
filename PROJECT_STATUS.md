## Implementation Notes

### Google OAuth Flow
The frontend utilizes the Firebase SDK to trigger a `signInWithPopup`. Once authenticated via Google, the frontend sends the user's `email`, `name`, `uid`, and `avatar` to the Express backend (`POST /api/auth/google`). The backend looks up the user; if they do not exist, a new MongoDB document is created with `provider: 'google'` and a conditionally bypassed password requirement. Finally, the backend issues a standard JWT token, seamlessly merging the OAuth session with the custom local architecture.

### JWT Integration
Tokens are generated by the User model's `generateAuthToken` method. The backend service (`sendTokenResponse`) sends the token both in the JSON payload and as an `HttpOnly`, `Secure` cookie, ensuring XSS and CSRF resilience. The frontend `api.js` Axios interceptor attaches the token to all outgoing requests.

### MongoDB User Storage
The `User.js` model handles both standard (`provider: 'local'`) and OAuth (`provider: 'google'`) accounts safely. The `password` field uses a dynamic validation function to only require a password for local signups. The database gracefully merges users if a local user later signs in with Google, linking their `googleId`.

### Protected Dashboard Flow
React Router v7 handles the frontend with a `<ProtectedRoute>` wrapper that verifies the `isAuthenticated` state from `AuthContext`. If unauthorized, users are redirected to `/login`. The backend secures its endpoints using a `protect` middleware that validates the provided JWT signature before attaching the user to the `req` object.
